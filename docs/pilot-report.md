# «Билет дня». Отчёт о приёмке

27 ноября 2026 года подготовлен воспроизводимый локальный сценарий для Telegram-бота и Mini App. Система связывает импорт и эталоны, групповое расписание, личные ответы, проверку и интервальные повторы. Публичный пилот остаётся этапом приёмки.

## Что проверено

Сквозной сценарий запущен на пустой PostgreSQL с подставными Telegram и моделью. `TestClient` прошёл HTTP webhook и API Mini App. Планировщик получил управляемые даты для вечернего среза и повторов. Полный набор на тестовой PostgreSQL прошёл **41 тест**.

Локальная конфигурация Compose подняла API, воркер и прокси. PostgreSQL применила 9 миграций. Клиент проверил цепочку тестового сертификата Caddy, получил `200` на `/health`, `/app/` и `/app/app.js`, а запрос `/v1/groups` без сессии получил `401`.

## Метрики

Локальный замер проведён на десяти одновременных синтетических ответах. Значения подтверждения и доставки записаны после успешной отправки подставному Telegram. Замер чтения карты выполнен отдельно на десяти одновременных авторизованных запросах к API.

Фактический прогон на endpoint НГУ дал **33 из 36 оценок в пределах ±1 балла (91,7%)** для `qwen3.8-flash-next` с `--thinking off`. С исходным режимом было 15 из 36. Набор синтетический, эталонные баллы подготовил Codex по рубрикам. Независимая разметка команды и проверка второй модели остаются этапами калибровки. [Отчёты AI-04](../evals/README.md)

## Приёмка на живом стенде

1. Владелец стенда поднимает API, воркер и БД на VPS, настраивает HTTPS и передаёт секреты владельцам отдельно. Нужны домен, тестовый Telegram-бот и доступный модельный профиль. [Запуск и восстановление](../deploy/README.md)
2. Участник команды повторяет локальный запуск по README, затем проходит сценарий в тестовом чате с организатором и тремя студентами. Проверяются открытие Mini App внутри Telegram, реальные публикации, ответы и доставка оценок. [Сценарий демонстрации](demo/README.md)
3. На живом стенде записываются задержки подтверждения, оценки, карты и плановых публикаций, число сбоев и версии моделей. Команда подтверждает разметку контрольной выборки и сравнивает доступные модели.
4. После тестовой группы проведите пилот в двух–трёх группах. Посчитайте ежедневное число ответивших, возвраты к повторным билетам, обращения по эталонам и сбои, которые мешали ответить. Для естественной проверки обоих интервалов заложите учебные даты после первого слабого результата и первого повтора.

Адрес VPS и настройки тестового Telegram-бота отсутствуют в конфигурации рабочего пространства. Живые замеры, независимый запуск товарищем по команде и отзывы групп пока ожидаются.

В журнал пилота записывайте дату, этап, ожидаемое и фактическое поведение, внутренний ID события, решение и результат повторной проверки. Владелец Telegram передаёт участникам [инструкцию пользователя](user-guide.md).
