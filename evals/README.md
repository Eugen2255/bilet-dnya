# Калибровка оценки ответов

`answer-calibration-v1.json` содержит 36 синтетических ответов по шести рубрикам. В каждой рубрике есть по два корректных перефразирования, неполных ответа и ответа с фактической ошибкой. Для каждого примера записаны зачтённые пункты `goldCovered`, фактические ошибки `goldErrors` и ожидаемый балл `goldScore`. Codex подготовил исходную разметку по рубрикам. Независимая разметка участниками команды остаётся этапом приёмки.

Выполняйте команды из корня репозитория в установленном Python-окружении.

```sh
python -m app.ai.calibrate evals/answer-calibration-v1.json --validate-only
python -m app.ai.calibrate evals/answer-calibration-v1.json --model-id qwen3.8-flash-next --pause 0.15 --output data/calibration-flash-default.json
python -m app.ai.calibrate evals/answer-calibration-v1.json --model-id qwen3.8-flash-next --thinking off --pause 0.15 --output data/calibration-flash-off.json
python -m app.ai.calibrate evals/answer-calibration-v1.json --profile fallback --output data/calibration-fallback.json
```

Профиль `primary` читает `MODEL_PRIMARY_*`, профиль `review` использует основной endpoint и `MODEL_REVIEW_ID`, профиль `fallback` читает `MODEL_FALLBACK_*`. `--model-id` и `--thinking` задают параметры одного прогона. `--pause` задаёт интервал между запросами в секундах. Команда оценивает каждый профиль отдельно одним адаптером `Grader` и сохраняет ID и категорию синтетического примера, ожидаемый и полученный баллы, код сбоя и время запроса.

Опция `--thinking off` отправляет поддерживаемый Qwen параметр `chat_template_kwargs.enable_thinking=false`. Для соответствующей настройки воркера задайте `MODEL_PRIMARY_THINKING=false` или `MODEL_FALLBACK_THINKING=false` для конкретного endpoint с поддержкой параметра. Для прогона `calibration-flash-default.json` оставьте `MODEL_PRIMARY_THINKING` пустым. [Qwen vLLM deployment](https://github.com/QwenLM/Qwen3/blob/main/docs/source/deployment/vllm.md)

Для сравнения используйте отчёты с одной контрольной суммой `datasetSha256` и версией `promptVersion`. Порог приёмки составляет 85% попаданий в ±1 балл. `withinOneRate` считается от всех примеров, включая сбои. Отчёт также содержит точные совпадения, среднюю абсолютную ошибку и P95 задержки успешных запросов. Разбивка по категориям помогает проверить, как модель справляется с неполными ответами и фактическими ошибками.

Для ручной приёмки проверьте каждый `answer` по указанной рубрике. При расчёте `goldScore` умножьте долю зачтённых пунктов на 5 и округлите до ближайшего целого с округлением половины вверх. Вычтите число разных фактических ошибок и ограничьте результат диапазоном от 0 до 5. Например, три зачтённых пункта из четырёх и одна ошибка дают 3 балла. Решение о резервной модели принимается после прогона с утверждённой разметкой.

## Прогон на endpoint НГУ

27 ноября 2026 года endpoint вернул в списке моделей `qwen3.8-flash-next`. Оба прогона использовали один набор и промпт `grade-v1`.

| Запрос | В пределах ±1 | Точные совпадения | Сбои | P95 успешных запросов |
| --- | ---: | ---: | ---: | ---: |
| [Режим провайдера](results/nsu-qwen3.8-flash-next.json) | 15 из 36 (41,7%) | 15 | 21 | 9,16 с |
| [Отключённый режим рассуждения](results/nsu-qwen3.8-flash-next-thinking-off.json) | 33 из 36 (91,7%) | 33 | 3 | 11,83 с |

В двух повторённых сбойных примерах исходный запрос достиг лимита в 500 токенов. При `--thinking off` те же примеры вернули завершённый ответ за 175 и 149 токенов. Во втором полном прогоне оценки получены для 10 из 12 примеров с фактическими ошибками, 12 из 12 перефразирований и 11 из 12 неполных ответов. Два запроса вернули `MODEL_UNAVAILABLE` примерно через 12 секунд, один вернул `INVALID_GRADE_POINT_IDS`. P95 описывает успешные запросы каждого прогона, включая время повторного запроса при `429`.

Сравнение с `Qwen3.8-27B` и резервной моделью ждёт доступных профилей. Приёмка ждёт независимой разметки команды.
